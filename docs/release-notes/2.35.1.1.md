# OpenTok.Net.Android 2.35.1.1

A native SDK bump: `opentok-android-sdk` 2.34.1 -> **2.35.1**, and with it `com.vonage:webrtc`
121.1.101 -> **145.0.113** (WebRTC M145). All three packages move:

| Package                                  | 2.34.1.4    | 2.35.1.1    |
| ---------------------------------------- | ----------- | ----------- |
| `OpenTok.Net.Android`                    | 2.34.1.4    | 2.35.1.1    |
| `OpenTok.Net.webrtc.Dependency.Android`  | 121.1.101.1 | 145.0.113.1 |
| `OpenTok.Net.Transformers.Android`       | 2.34.1.4    | 2.35.1.1    |

2.35.0 was never released from this repository. Vonage published it to Maven Central on
2026-08-11 and followed with 2.35.1 nine days later; only 2.35.1 appears in their release notes,
and the two differ solely in native code — their `classes.jar` public surfaces are identical, so
everything below about 2.35.x applies to both. This release takes 2.35.1 directly and closes the
upstream-drift issues #8 and #9.

This release is **source-breaking** in two places, described first.

## Breaking: `Com.Vonage.Webrtc.Logging.TraceLevel` is gone

WebRTC M145 removed the `Logging.TraceLevel` enum and `Logging.EnableTracing(string, EnumSet)`,
the one method that took it, from `com.vonage:webrtc`, so the binding no longer has them either.
Code that referenced `Logging.TraceLevel` needs to drop it; `Logging.Severity`,
`Logging.EnableLogToDebugOutput` and the `Logging.D/E/W/V` methods remain.

That is the only removal a typical OpenTok app would reach. The 121 -> 145 jump is two years of
engine releases, and the rest of what moved in the bound `Com.Vonage.Webrtc` surface is the
engine's own plumbing, which an app drives through the OpenTok SDK rather than directly. For
completeness, checked member by member against both jars:

* `VideoEncoder`/`VideoDecoder` (and `WrappedNativeVideoEncoder/Decoder`, the `Libvpx*`, `LibaomAv1`
  and `*Fallback` codecs) replace `createNativeVideoEncoder()` / `createNativeVideoDecoder()` with
  `createNative(long webrtcEnvRef)`; `AudioProcessingFactory.createNative()` gains the same
  parameter; `AudioDeviceModule.getNativeAudioDeviceModulePointer()` becomes `getNative(long)`.
* `RtpTransceiver.setCodecPreferences` now returns the new `RtcError` instead of `void`.
* `PeerConnection.RTCConfiguration.activeResetSrtpParams` and
  `PeerConnectionFactory.fieldTrialsFindFullName` are removed; so are five string helpers on
  `WebRtcAudioUtils`.
* `NetworkChangeDetector.NetworkInformation`'s constructor takes an additional `NetworkSlice`.
* New: `Environment` / `Environment.Builder`, `RtcError`, `RtcException`, `AudioFrameProcessor`,
  `EglRenderer.RenderListener`, `PeerConnection.PortAllocatorFlags`, and the `org.jni_zero`
  annotations the engine is now built with.

## Breaking: `BaseVideoRenderer.Frame.GetMetadata()` is gone

Vonage removed `BaseVideoRenderer.Frame#getMetadata()`, and the `BaseVideoCapturer` frame-metadata
methods alongside it, in 2.35; they had been deprecated since 2.33.0. A custom renderer that read
per-frame metadata has no replacement.

## Added: target scalability mode (beta)

`PublisherKit.SetTargetScalabilityMode(string)` and `PublisherKit.TargetScalabilityMode` let a
publisher pick the number of spatial and temporal layers it encodes, in the form WebRTC uses
(`"L1T1"`, `"L3T3"`, and so on). Vonage marks this beta, and notes that a non-default mode can
change how a subscriber's `SetPreferredResolution` / `SetPreferredFrameRate` behave.

## Added: `ProxyReceiver.ForceSetProxy(string, int, string, string)`

A four-argument overload of `ForceSetProxy` taking proxy credentials alongside the host and port.

## Changed: more of the SDK's internals are public

2.35's `classes.jar` is shrunk less aggressively than 2.34.1's. A number of members that were
package-private or obfuscated before are now public Java members, and so are now bound:
`...JNI` callback methods on `Session`, `PublisherKit` and `SubscriberKit`, `finalize()`
overrides, `Utils`, `BluetoothManager`'s SCO helpers, and similar. None of it is documented API,
and none of it is meant to be called from an app — it is listed so that it is not mistaken for
something new. It is not hidden by `Metadata.xml`: that would be guessing at what Vonage considers
internal, and the next release could move the line again. The new `finalize()` overrides are what
the 44 `CS0465` warnings in a binding build are about; they are the generator's faithful rendering
of the Java and are harmless.

One of these needed a transform. `SubscriberKit.error(SubscriberKit, int, String)`, bound as-is,
is a method named `Error`, and the generator then dropped the `SubscriberKit.Error` **event** —
silently: the package built, and the sample app was what failed, with `CS1656` on
`subscriber.Error += ...`. The method is renamed `ErrorInternal` in `Metadata.xml`, which gives
the event its name back. `Session.Error` and `PublisherKit.Error` were never affected;
`BindingApiTests.Error_events_survive_the_sdks_own_error_methods` now asserts all three against
the packed assembly, on every target framework.

With that in place, a member-by-member comparison of the packed `OpenTok.Net.Android` assembly
against 2.34.1.4's shows exactly one removal outside the obfuscated `Com.Opentok.Otc` namespace
and the equally obfuscated `Grafika.Gles` GL helpers: `BaseVideoRenderer.Frame.GetMetadata()`,
above.

## Unchanged

* `minSdkVersion` is still 24, so `SupportedOSPlatformVersion` stays put.
* The transitive pins `opentok-android-sdk` declares are unchanged from 2.35.0's (and
  `com.google.flogger` 0.6 and `com.google.guava` 31.1-android from 2.34.1's), taken from the
  2.35.1 POM rather than assumed.
* `OpenTok.Net.Transformers.Android` rides the SDK's version line, and its POM still declares
  `mltransformers-ps16k` 4.1.65 and `mltransformersaudionoisesuppression-ps16k` 1.1.33. Only
  `libopentok_transformers.so` changed between 2.35.0 and 2.35.1; the two ML libraries are
  byte-identical.
* Every `Metadata.xml` transform in both bindings still resolves against the new jars: the
  `SubscriberKit` `onDisconnected` collision fix and the listener parameter names on the OpenTok
  side, and `StatsReport.Value`, `WrappedNativeVideoEncoder.getScalingSettings` and
  `TextureBufferImpl.getType` on the webrtc side.
* Targets: `net8.0-android34.0`, `net9.0-android35.0`, `net10.0-android36.0` for the binding and
  its webrtc dependency; `net8.0-android34.0` and `net10.0-android36.0` for the transformers, as
  2.34.1.4 set out.

## From Vonage's 2.35.1 notes

Besides the scalability-mode API and WebRTC M145: the SDK's `compileSdk`/`targetSdk` move to 37
(Android 17) — which does not change what this binding targets — its audio-focus handling moves
from `AudioManager.requestAudioFocus()` to `AudioFocusRequest`, and a crash/freeze on rapid
background-to-foreground transitions during a video session is fixed.

## The sibling

`OpenTok.Net.iOS` moves to 2.35.1.1 alongside this.
